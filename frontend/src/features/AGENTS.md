# FRONTEND FEATURES KNOWLEDGE BASE

## OVERVIEW

`frontend/src/features/` owns the active protected route modules mounted by `src/app/router`, while `src/pages/` remains the oracle-compatible source for legacy page clusters and helper surfaces still reused by feature routes and tests.

## STRUCTURE

```text
features/
├── endpoints/        # `/route/endpoints` feature page and endpoint dialogs/hooks (`endpoints/AGENTS.md`)
├── loadbalance/      # `/route/ban-policies` page with strategy collection, mutation, and impact owners
├── models/           # `/models` list feature, `/models/$modelId` detail adapter, and `models/export/` client-config export owners
├── observe/          # `/observe` dashboard adapter, scoped attribution views, and routing-health query/context, event, and current-state owners
├── pricing/          # `/route/pricing` feature page with collection/editor/detail/import owners
├── proxy-keys/       # `/system/proxy-keys` global proxy-key surface: ledger, four mutation lanes, secret session, access panel (`proxy-keys/AGENTS.md`)
├── routing-health/    # Observe 路由健康 tab: global current state, events timeline, reset flow
├── runtime-self-test/ # Shared four-layer runtime self-test: effective origin, curl builder, direct runner, dialog
├── request-logs/     # `/observe/requests` list and audit detail adapters
└── settings/         # `/system/settings` feature adapter
```

## CONVENTIONS

- For UI/UX, frontend visual, styling, layout, component, page, dialog, drawer, table, form, status/feedback, or navigation changes, follow `frontend/DESIGN.md`: use `@/shared/design-system` before `@/components/ui`, preserve the Google Admin Console / Material Design 3 operator direction, use semantic tokens, operator surface classes, density variables, and required operator components, keep route state and API calls out of design-system components, and avoid adding compatibility wrappers under `@/components`.
- Do not add decorative gradients, blur blobs, heavy shadows, marketing hero layouts, raw Tailwind status colors, page-local color blends, or ad hoc dark-mode overrides outside the `frontend/DESIGN.md` contract.
- Keep route modules thin at the boundary: route params/search and feature-local composition belong here; reusable backend contracts stay in `../lib`, and oracle page clusters stay in `../pages` until migrated.
- The `models/export/` surface owns the managed Pi-only 0.84.3 `prism-pi-models.json` (Pi `models.json` format) export; there is no platform choice and no manual upload. Selection truth comes from the backend source snapshot (first load adopts every selectable model, refetches intersect the operator's current selection); the operator supplies the Prism origin and provider id, and the credential modes are an omitted key slot or one explicitly included, trimmed, non-empty final-dialog string. Pi 0.84.3 rejects an empty `apiKey`. Never read Prism endpoint keys or derive the client URL from an upstream endpoint. Source/render calls bypass HTTP caches, key-bearing render responses never enter a query cache, and closing results or leaving the route clears content and revokes Blob URLs.
- Each model row's Pi coordinate is composed by `PiBindingCell.tsx` through the shared `usePiBindingController` and the `models/catalog/pi/` dialogs, with refresh, sparse override, and dropped-field evidence split into their named components. Bind and rebind share ONE entry, `PiBindingSourceDialog.tsx`, for every model whose `pi_api` is determinable — including rows the default flow reports as `not_in_catalog`/`api_mismatch`, which previously had no binding affordance at all; a model with no Pi text API mapping gets no entry. The dialog keeps the two discovery layers visibly separate: the default exact candidates (`pi_candidates`, complete Prism `model_id` case-sensitive plus same final Pi API) and an explicit bounded directory search (`POST .../pi/search`, model-id-only case-insensitive literal). Nothing is ever preselected in either layer, a one-hit search is still only evidence, and confirm stays inert until the operator names a coordinate or accepts the sole exact candidate (which keeps the `single_candidate` shortcut). Search responses remain dialog/model scoped; the selected layer supplies the exact catalog revision/status and Prism export identity used by bind, stale evidence is read-only, and candidates expose name plus template summary before selection and full evidence before confirmation. Row actions beyond three collapse into a `DropdownMenu` overflow per `DESIGN.md`.
- The two Provider ID data domains stay lexically distinct: the exported file's provider map key is labelled 导出 Provider 键名 in the destination panel and described as operator input, while a binding's pi.dev origin is 目录 Provider. Neither is ever rendered as bare `Provider ID`, and a directory provider never supplies or overrides the exported key.
- Live pi.dev candidates (`pi_candidates`/`candidate_status`) are discovery-only and always shown separately from the persisted binding (`pi_selected`/`pi_binding_status`/`pi_binding_renderable`/`pi_binding_prism_model_id`). Multiple candidates require an explicit coordinate even when templates match, and `PiCandidateEvidence.tsx` shows the selected candidate's seven safe fields after confirmation. The override editor shows source/override/effective values for all seven safe leaves and submits only fields explicitly set to a value or restored to null. All Pi mutations and the paged directory search live in the shared `usePiBindingController.ts`; after every successful mutation the host's authoritative `reconcile()` re-reads (the export host refetches the whole source snapshot and intersects the selection, the detail host refetches `GET /models/{id}/pi`), and no host patches state optimistically. Directory rows, freshness, Prism identity, query nonce, and revision are committed atomically under the shared pager's generation; late responses cannot mutate freshness after their rows are rejected. Search state resets when the dialog/model changes, appends are single-flight and deduped, failures keep loaded rows with a same-offset retry, and a revision rollover withdraws the mixed list, re-reads offset 0, clears the selection, and remains visibly acknowledged by the operator. Generation is blocked only when `pi_binding_renderable` is false; live-catalog/template drift may be `bound_drifted` while the frozen binding remains renderable. Full-content copy, fixed-name/MIME download, and a real new-tab raw view reuse exactly one rendered content string. Pi's separate merge-fragment action parses that same string locally and copies only `{ "<provider_id>": { ...provider... } }\n` for insertion beneath an existing `models.json` `providers` object; it never re-renders or implies replacing other providers.
- Keep global control pages free of profile-scope assumptions unless backend route scope explicitly says otherwise.
- Observe Trend and Errors share URL-backed `scope`; Activity always uses an independent ingress query context, while Terminal Targets own a final/attempt sub-view that re-reads the selected Endpoint.
- Trend/Errors render the scoped request-log coverage lane and export each fragment with its own scope/bounds/caliber/coverage. Errors links always open Requests attempts with the signed replay filters; route-attempt links pin `row_kind=upstream`.
- Prefer feature-local schema/payload builders beside the feature page when they are only used by that route.
- Keep Ban Policy strategy collection/read, CRUD/default mutations, and impact cursor pagination in their named feature owners; the page hook only composes them.
- Keep pricing-template collection/editor mutations, usage/history detail reads, and import preview/commit in their named feature owners; preserve the two-phase import contract and last-good states.
- Keep proxy-key ledger/query state, create/edit/rotate/delete mutation lifecycles, mutation reconciliation/error mapping, and the one-time raw-secret session in their named owners; mutations must preserve cache invalidation, capacity reconciliation, and no-store secret handling.
- Keep request-log attempt reads and ingress-chain reads in separate owners; the page hook only selects and combines the active view while preserving committed filter metadata for cross-view fallback.
- Keep routing-health signed query context, event paging/detail selection, Current State reads/resets, and presentation in their named owners; `RoutingHealthTab.tsx` only composes them.
- Keep the model-export host adapter (`useModelExportSource.ts`) owning only the authoritative source query, batch selection, filters, per-row Pi view mapping, and reconciliation; Pi binding mutations and directory search live in the shared controller. Render/key/result lifecycle stays in `useModelExportRender.ts`; `ModelExportPage.tsx` only composes page presentation. `PiBindingCell.tsx` composes the shared `models/catalog/pi/` dialogs and evidence components; the model detail page mounts the same controller through `ExternalCatalogSourcesSection`/`PiDevCatalogPanel` so both hosts share observable behavior and payloads. `ExportKeyDialog.tsx` and `ExportResultSheet.tsx` remain the credential-decision and generated-result presentation owners; `PiBindingCell.tsx` composes the named Pi binding dialogs/evidence components and stays out of `ModelExportModelTable.tsx`, which only lays out rows and columns.

## ANTI-PATTERNS

- Do not add new protected routes without updating `../app/router/rewriteRoutes.ts`, `../app/router/appRouter.tsx`, navigation metadata, tests, and these docs.
- Do not move backend API calls directly into presentational tables when a feature data hook already owns the mutation/fetch flow.
