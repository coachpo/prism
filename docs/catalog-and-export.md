# Catalog Metadata, Pricing Import, and Client Export

Shipped behavior of models.dev catalog binding, source-linked pricing import, and Pi and OpenCode client configuration export. Wire fields are in the [Management API](management-api.md#model-catalog-metadata-modelsdev); the loading procedure is in [operations](operations.md#client-configuration-export-quick-guide).

## Product Behavior

### Catalog Metadata and Source-Linked Pricing (models.dev)

- Prism can bind each model to one offering of the fixed official models.dev catalog (`https://models.dev/api.json`, MIT License) and show its metadata on the model detail page. Binding happens through a unique exact ID auto-match (committable preview only; ambiguous or missing IDs require an explicit provider + model ID choice) or manual coordinates, and is never re-guessed once bound.
- The panel always distinguishes source values (refreshed only by explicit operator refreshes), per-field manual overrides (never touched by refreshes), and the effective merge. Every models.dev write locks the model row before the optional binding row. Bind re-verifies the confirmed Prism identity and catalog ETag; refresh commits against the exact catalog revision, binding coordinate, and `updated_at` token previewed; sparse override confirms the displayed coordinate before merging over the locked current row; bulk override clear and unbind carry the coordinate/`updated_at` snapshot the operator confirmed (unbind is idempotent once the row is gone). Every conflict (`409 models_dev_model_changed` / `models_dev_binding_stale` / `models_dev_catalog_stale`) writes nothing, so neither stale remote data nor a locally newer rebind/override can be clobbered and two operators editing different fields on the same offering never lose updates. Reading is honest too: a failed first read renders an error+retry surface and never a fabricated "未绑定", a failed re-read keeps the last good metadata under a single staleness badge with the last success stamp, `fetched_at` renders through the global timezone, and only a successful `bound:false` response may show the unbound conclusion. All `/api/models/{id}/catalog*` responses are `private, no-store`, and the model detail page composes models.dev and pi.dev under one 外部目录来源 section whose two panels load, fail, and recover independently.
- Source-linked pricing is reachable from **both** surfaces and they share one protocol and one set of components: the per-Target action on the model detail page, and the **从目录导入** entry on `/route/pricing`. Automation only discovers and prefills; every write needs a fresh preview and an explicit operator confirmation, and no path ever auto-selects the first candidate, the lowest price, or silently prices every Target.
- On `/route/pricing` the operator picks a Prism model. A unique exact ID match advances straight into the price preview. Zero or multiple matches stop at a bounded, paged, case-insensitive candidate search (optionally widened past the API family's own providers) where the operator must pick coordinates explicitly; the operator can load through the reported total instead of being limited to the first 20 results, and replace/append failures never masquerade as an empty list. The ambiguous `openai`/`anthropic`/`google` case still refuses to auto-bind. This surface defaults to creating or refreshing the source-linked template with **no** Terminal Target preselected, and assigning nothing unless the operator checks targets on purpose. Importing prices never binds the model.
- The model detail action is the same dialog with one difference: the current Terminal Target is preselected and locked, and extra targets are an explicit opt-in. Changing the selected target set at any time invalidates the previous preview and re-reads it, because the preview hash covers every target's CAS state.
- The preview shows both ends of the mapping and the whole price: the Prism model, the `provider/model` models.dev coordinate, the fixed `USD`/`PER_1M` unit, all five components (input, output, cache read, cache write, reasoning) per card, tier threshold, catalog fetch time, and every stable incompatibility reason in operator language; revision hashes remain protocol data. An explicit catalog `0` renders as `0` and never collapses into the unconfigured marker; an absent cache component renders as unconfigured. An absent reasoning price is planned at the same card's output price, because models.dev consumers bill reasoning tokens at the output rate; an explicit catalog reasoning value, including `0`, is kept. A linked template whose reasoning price is unconfigured therefore previews as drift. When a plan cannot be expressed losslessly the commit stays disabled with a stated reason and the server writes nothing.
- Committing creates or reuses the one **live** source-linked pricing template for that offering. Creating it records the first catalog revision; restoring confirmed manual price drift appends another immutable catalog revision, while unchanged template-only reuse leaves template and target state untouched instead of fabricating history. Selected Terminal Targets are assigned atomically through the existing double CAS, and any conflict rolls the template revision, mutation evidence, generation changes, and all target assignments back together. If the template was hand-edited since, the dialog requires explicit confirmation before overwriting. Every successful catalog commit still advances the runtime planning-cache generations through the platform mutation owner, and the frontend immediately refreshes the pricing template list, the Terminal Target option cache, and the affected target rows so every view agrees. Soft-deleting a source-linked template releases its coordinates, so the same offering can be imported again as a new live template while the retired template and its full revision history are retained.
- Template and revision views expose where prices came from: the pricing table shows the offering coordinate under the template name, and the revision history labels each revision as manually authored or a catalog import and shows its price changes and time without exposing catalog revision hashes.
- Catalog fetching is restricted to HTTPS, same-origin redirects, a 10-second timeout, and a 16 MiB budget, revalidates through ETag/304, collapses concurrent fetches, and never runs inside a database transaction. There is no scheduled synchronization: every read of fresh data is an explicit operator action. Pi directory prices stay out of this flow entirely — pi.dev `cost` is parsed only to be discarded, and models.dev remains the single catalog price authority.

### Client Model Configuration Export

- Both client source responses carry an independent backend readiness result from the same pure renderer used by export. Ready means the selected client can render from the sampled facts; it does not assert live upstream health. Blocking reasons link to the owning model editor. Catalog failures distinguish timeout, malformed format, unsupported version, failed content verification and unavailable transport; last-good evidence and saved bindings stay separate, and an explicit retry can recover without fabricating limits or prices.

- The standalone `/route/models/export` page defaults to Pi and offers OpenCode 1.18.27 as a separate target. Switching targets resets and cancels the previous source, selections, credential dialog and generated result; late responses cannot cross targets. The Pi target generates deterministic Pi 0.84.3 `prism-pi-models.json` (Pi `models.json` format) from Prism-managed model truth, behind management authentication, with the pi.dev structured directory (`https://pi.dev/api/models`) as the single template source and a persisted per-model binding as the render authority. Pi selection requires both structural eligibility and backend renderer readiness; missing/blocked readiness cannot be selected, including through a preset. Binding repair stays available without selection, and a repaired model is explicitly selected afterwards. The operator supplies an HTTP(S) Prism gateway origin and a provider id (default `prism`); the export never substitutes a reachable upstream endpoint URL and never uses pi.dev provider/api/baseUrl/cost/headers/samplingParams/fallback/routing to override Prism identity, protocol, gateway, credential selection or pricing truth.
- The backend pi.dev typed catalog uses restricted HTTPS transport (4 s timeout, same-origin redirects, 16 MiB budget, `Accept: application/json`, `ETag`/`If-None-Match` and `304` revalidation, `singleflight` coalescing, `last-known-good` retention, `X-Pi-Model-Catalog-Minimum-Version` validation against Pi 0.84.3, strict `Content-Type: application/json`, HTML rejection, and no browser fetch). The trusted `catalog_revision` is the verified SHA-256 of the response body (`sha256-…`); a missing/mismatched header fails closed and ETag remains a `304` validator only. Candidates use complete case-sensitive `model_id` equality plus final Pi API compatibility (`openai-responses` for `dual_native`/`responses_only`, `openai-completions` for `chat_completions_only`, `anthropic-messages` for Anthropic, `google-generative-ai` for Gemini), never names/slugs/contains/fuzzy. `0`/`1`/`many` states describe the fetched catalog revision, so candidate counts may change when that revision changes. Multiple coordinates—even with identical sanitized templates—always require an explicit operator choice. Separately, `POST /api/models/{model_config_id}/pi/search` is the bounded directory discovery entry for every model whose final Pi API is determinable, including `not_in_catalog` and `api_mismatch` rows: model-id-only case-insensitive literal containment (never provider, display name, or fuzzy), same-final-Pi-API only, ranked exact/prefix/substring then provider/id over the whole same-API hit set before the `offset` window is cut, default 20 and max 100 with append paging through the reported `total` (pages echo their window and `fetched_at`/`checked_at` separately), never preselected, and it writes nothing. `GET /api/models/{model_config_id}/pi` is the per-model Pi management read for the model detail panel: model identity including Prism's own final `pi_api`, one catalog evidence block (`fresh`/`stale` last-known-good/`unavailable`), live exact-candidate evidence, and the persisted binding truth from one read-only `REPEATABLE READ` snapshot — never export targets, pricing, source digests, credentials, or render results, and a catalog outage never manufactures an unbound binding. The model detail panel and the export row actions drive the same shared binding controller and dialogs, so both hosts issue byte-identical bind/refresh/override/unbind payloads and always reconcile through their own authoritative re-read. Each candidate's `compat` is sanitized through its concrete Pi 0.84.3 API allowlist; cross-API/unknown/routing/fallback fields, headers, sampling parameters, and unknown optional fields become sorted read-only `dropped_fields` evidence. Manual overrides reject rather than silently drop those keys.
- `model_pi_catalog_bindings` (`000027_model_pi_catalog_bindings.sql`, purely additive) freezes at most one binding per model: the selected coordinate, `bind_source`, trusted `catalog_revision`, stamps, seven safe `source_*`/`override_*` pairs, and sorted `source_dropped_fields`. It is independent of the models.dev table used by [Catalog Metadata and Source-Linked Pricing](#catalog-metadata-and-source-linked-pricing-modelsdev). `POST /api/models/{id}/pi/bind` requires `expected_catalog_revision` plus `expected_prism_model_id`/`expected_pi_api` and re-verifies all three under row lock, so a stale preview or a concurrent Prism rename can never commit. An explicit coordinate must be a real entry in the fetched revision carrying exactly the model's current final Pi API, which makes a deliberate cross-directory `catalog_model_id` bindable while a cross-API one rejects `422 pi_candidate_api_mismatch`; without coordinates the unchanged 0/1/many exact flow decides. Each bind freezes the confirmed Prism identity into `prism_model_id_at_bind` (`000028_model_pi_binding_identity.sql`, additive and data-preserving, backfilled from `catalog_model_id` so existing rename drift survives instead of being healed), and that snapshot — not the directory id — is what renderability compares against. Repeating the same coordinate with the same identity is a no-op; repeating it after a Prism rename advances the identity snapshot and `updated_at` CAS token while keeping frozen source, overrides, revision, `fetched_at` and `bind_source`; changing the coordinate clears overrides. Refresh preview returns source/dropped diffs plus coordinate, API, binding-update, and catalog-revision tokens; commit must match all five expected values under row lock before changing only source/dropped fields. `PUT` override is sparse across all seven leaves, validates `compat` against the bound API, and treats explicit null as per-field restore; delete clears all overrides, and unbind removes the row. The directory search plus the six bind/refresh/override/unbind routes are `Default-profile`, `M2`, planning-neutral, `private, no-store`.
- `GET /api/models/exports/pi/source` and `POST /api/models/exports/pi/render` share `Default-profile`, `M3`, `planning-neutral`, `private, no-store`; Pi and OpenCode have separate literal source/render routes. `source` combines one best-effort live fetch with one consistent DB snapshot and separates live candidate evidence from persisted binding evidence (`pi_selected`, `pi_binding_status`, `pi_binding_renderable`, source/override/effective metadata, dropped fields, and stamps). Live coordinate/template drift is visible and refreshable while a compatible frozen row stays renderable; changing the Prism full model ID or final Pi API makes it non-renderable until the identity is re-confirmed. `pi_binding_prism_model_id` publishes the frozen identity and `pi_api` the model's final Pi API, so one row can honestly read `not_in_catalog` while still being `bound` and renderable through a deliberate cross-directory bind. `render` performs no network I/O and reads no live or LKG catalog: it requires the source digest and exactly one matching coordinate assertion for every selected model, returns `422 candidate_unselected` for a missing binding/assertion and `422 candidate_invalid` for an extra/mismatched/incompatible coordinate (with `model_config_id`), and renders from the frozen effective template alone. The digest covers each binding's full coordinate, frozen Prism identity snapshot, revision, effective template, and dropped evidence but excludes the current live-fetch outcome and any directory search result, so switching between identical templates still changes it while catalog reachability does not.
- Output preserves only safe pi.dev leaves `name`/`reasoning`/`input`/`contextWindow`/`maxTokens`/`thinkingLevelMap`/`compat`; Prism's `model_id`, mapped Pi `api`, gateway-derived `baseUrl`, provider key, credential choice, and current pricing remain authoritative. When selected models share one derived client URL, only the provider definition carries `baseUrl` and every model inherits it; mixed URLs remain per-model and produce `mixed_base_urls`. Pricing stays `fail-closed` across all actually reachable Terminal Targets for every accepted operation (USD/`PER_1M`, five components, `reasoning_price == output_price`, lossless tier mapping for Pi's single strict positive tier; `pricing_component_missing` on any null component including `reasoning_price=null`, plus distinct warnings for no template, currency/unit mismatch, target conflict, peak/valley and tier unrepresentable; explicit `"0"` alone means free). Source headers/samplingParams/fallback/routing are never proxied into the file.
- Credentials have only `include=false` (omit) or `include=true` with a manually entered, trimmed, non-empty string; Pi 0.84.3 rejects an empty `apiKey`, so the dialog blocks it and the backend returns `422 credential_api_key_required` defensively. Export never reads stored endpoint keys and the typed value never enters source URLs, PostgreSQL, query caches, browser storage, logs, errors or warnings. All `source`/`render` and error responses are `private, no-store`; the rendered file ends with exactly one newline, `content_sha256` is the SHA-256 of those UTF-8 bytes, the response carries the fixed `prism-pi-models.json` name and `application/json;charset=utf-8` MIME, and full-content copy, Blob download and a true new-tab raw view reuse the same bytes. The browser may also copy a locally derived `{ "<provider_id>": { ...provider... } }\n` fragment for merging beneath an existing `models.json` `providers` object. Both copy actions use the shared clipboard helper, including the textarea fallback when Clipboard API is absent or rejects on a plain-HTTP LAN origin; the copied state appears only after success. Closing the result or leaving the route clears content and revokes its Blob URLs.
- The Pi target preserves its binding workflow without default-model or upload-enhancement controls, and honestly distinguishes live catalog `fresh`/`stale`/`unavailable`, `not_in_catalog`, `api_mismatch`, and `multiple` candidate evidence from persisted `unbound`/`bound`/`bound_drifted` binding status, shows the selected candidate's seven safe template fields and dropped paths before bind/rebind confirmation, surfaces refresh/override affordances per model, and keeps the provider-merge fragment. Bind and rebind share one 更换来源 dialog for every model with a determinable final Pi API, keeping the default exact-candidate layer and the bounded directory-search layer visibly separate; nothing is preselected, a one-hit search is still only evidence, the final export identity is shown before confirmation, and confirm is blocked unless the catalog is `fresh`. The two Provider ID domains are labelled distinctly — 导出 Provider 键名 for the operator-authored exported file key and 目录 Provider for a binding's pi.dev origin — and row actions beyond three collapse into an overflow menu.


- **OpenCode 1.18.27:** eligible enabled direct text entries export to `opencode-prism.json` using an independent `prism` or `prism-` custom provider key. Every model retains its complete Prism ID and carries its own SDK and gateway URL: Chat Completions uses `@ai-sdk/openai-compatible` with `/v1`, Responses and `dual_native` use `@ai-sdk/openai` with `/v1`, Anthropic uses `@ai-sdk/anthropic` with `/v1`, and Gemini uses `@ai-sdk/google` with `/v1beta`. There is no provider-level `baseURL` override. A primary conversation operation must be statically routable and its unchanged ID must be addressable by the existing runtime path grammar; Gemini IDs whose URL interpretation changes that identity are unavailable with a reason.
- OpenCode source and render read one read-only Default-profile snapshot each, using current reachable-target price facts and persisted models.dev source/override leaves. They never fetch either catalog, require Pi bindings, change metadata or invalidate runtime planning. Manual overrides take precedence for safe fields; names prefer Prism `display_name`, then a valid effective directory name, then the complete model ID. The page shows saved source, override, final value, provenance and missing/invalid reasons. Valid explicit false values, empty modality lists and expressible zero values remain distinct from absence. Context and output limits must be positive safe integers, and input/output individually cannot exceed context; an invalid limit group blocks that model. The existing metadata panel owns corrections.
- Only target-supported name/family/release date, attachment/reasoning/tool/temperature capability, modalities and limits are mapped. Custom variants, SDK options and interleaved reasoning are neither inferred nor edited. OpenCode may still apply model-ID/SDK-dependent defaults; automatic behavior is not a claim of manual reasoning adaptation. An explicit optional input limit of zero is preserved in configuration, but OpenCode can apply its own fallback budget when consuming it.
- OpenCode's four base costs are emitted only for identical standard USD/PER_1M current prices across all reachable targets, with all five Prism price components configured and reasoning price equal to output. Any tier, peak/valley schedule, missing component, currency/unit mismatch or conflict omits the entire cost object and explains why. No catalog price fills a gap, and a client zero estimate is not proof of free usage.
- `GET /api/models/exports/opencode/source` and `POST /api/models/exports/opencode/render` are `M3`, planning-neutral and `private, no-store`, including errors. The digest covers target version and actual consumed model, route/target, price and effective metadata/provenance facts; Pi bindings, live directory availability and unrelated or shadowed catalog fields do not affect it. Stale input returns `409 export_source_stale`; refresh and regenerate. Invalid selections or target parameters are rejected independently of frontend checks.
- OpenCode's no-key mode writes `env=[PRISM_API_KEY]` without `apiKey`; manual mode writes only the trimmed non-empty final key. Literal `{env:...}`/`{file:...}` inside supplied values are safely JSON-escaped to preserve their meaning through the client's configuration substitution. Credentials stay out of source responses, URLs, Prism persistence, caches and logs. The shared result sheet provides exact-byte full copy, download and new-tab viewing, plus a map to merge below singular `provider`; it clears content and Blob URLs on close, replacement, target switch or route exit. Loading and merging instructions are in [Operations](operations.md#client-configuration-export-quick-guide).

## Catalog Data Attribution

Model catalog metadata and catalog prices are sourced from [models.dev](https://models.dev), fetched read-only at operator request from its fixed official endpoint (`https://models.dev/api.json`). models.dev data is licensed under the MIT License (Copyright (c) 2025 models.dev); Prism stores only the metadata fields an operator explicitly binds or imports and never redistributes the catalog itself. Catalog lookups and metadata bindings stay on the management path and do not determine Prism runtime compatibility or routing. Accepted price imports become ordinary Prism pricing templates.
